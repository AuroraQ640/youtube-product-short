# YouTube 产品介绍短视频剪辑

## 默认交付标准

用户本次明确要求优先于以下默认值；沿用对话中已经确认的参数，不要重复询问。

| 项目 | 默认值 |
| --- | --- |
| 成片 | MP4，H.264 + AAC，横屏 16:9，1280×720 |
| 时长 | 严格少于 180 秒；选段时留出少量编码余量 |
| 大小 | 少于 200,000,000 字节，即 200 MB（十进制） |
| 速度 | 1.1-1.2×；以自然听感和字幕可读性为准 |
| 语言 | 保留原声；意大利语字幕烧录进画面，另附 UTF-8 SRT |
| 封面 | 1280×720，JPG 或 PNG；优先 KOL 手持产品 |
| 内容 | 产品亮相、核心卖点、配置、实测、接口/设计、总结；只使用原片支持的信息 |

200 MB 是上限，30-40 MB 仅是原 SOP 的经验体积，不为追求该范围过度降低画质。
若用户输入明显异常的体积单位，优先沿用当前对话已确认的 200 MB 约束并说明采用值；没有上下文且会改变输出时再澄清。

## 执行方式与授权范围

- 这是以 yt-dlp、Python、FFmpeg 为主的本地工作流，不依赖 ChatCut 连接。先发现已安装工具，使用实际路径，不硬编码某个用户或应用目录。
- 若用户明确要求使用剪辑软件及可编辑时间线，遵循该环境的工具流程，并如实说明可用连接；不要把脚本导出称为在编辑器内完成。
- 用户给出链接并要求成片后，完成素材获取、选段、字幕、封面、导出和检查。已有 SOP 足以确定的可逆步骤不增加确认关卡。
- 下载受网络限制时按宿主权限流程申请所需访问。遇到登录、付费或不可访问的源，只说明实际阻碍，不绕过访问控制。
- 只在当前任务工作区输出文件，保留原素材。剪辑交付不授权上传、发布或发送到外部账号。

## 一、素材获取

1. **读取信息**：获取视频标题、频道、时长、描述、音轨语言、字幕轨和格式列表，确认目标产品在原片中的名称。不要仅凭标题推断配置。
2. **选择媒体**：优先不高于 720p 的 MP4 视频流及原语言 M4A 音轨；明确选择原声，避免误取 YouTube 自动配音。分辨率低于 720p 时记录限制，不声称上采样恢复了细节。
3. **获取字幕**：优先使用已有准确意大利语字幕，否则获取意大利语自动字幕 VTT。字幕不可用时使用已接入的可靠转写/翻译能力；没有该能力则报告限制，不编造原话。非意大利语原声需生成或获取意大利语翻译字幕，并标注来源。
4. **合并或按段下载**：正常情况下获取并合并音视频。长片下载慢时，先用字幕选段，再下载所需区间，前后预留余量；记录每个片段在原片中的起点。已取得的媒体信息可在链接有效期间复用，不反复重新提取。

需要执行命令时，读取 [FFmpeg 工作流参考](references/ffmpeg-workflow.md)。其中格式 ID、文件名和时间均需按本次素材替换。

## 二、内容分析与选段

5. **解析字幕**：按原片时间码读取语义。YouTube 自动 VTT 常含滚动重复行，先去重；有词级时间标记时保留，普通句级字幕不要伪造词级精度。
6. **定位内容**：搜索产品名、配置、散热、接口、性能、价格、保修等，再阅读相邻句子。优先保留信息密度高、视觉展示清楚的片段。
7. **建立选段表**：通常选择 4-6 个核心片段，每段约 10-60 秒，可按语义调整。安排产品亮相 → 核心卖点 → 配置规格 → 实测 → 接口/设计 → 总结；允许为叙事调整顺序，不机械凑齐原片不存在的内容。

每段记录：原片起止秒数、保留理由、对应本地文件、该文件的原片起点、速度、预计成片位置。以完整句子和完整含义确定切点，保留关键主体、否定、比较对象及测试条件。不要把闲置功耗剪成最大功耗，也不要拼接出说话者未表达的推荐或结论。

用 `总时长 = Σ[(原片结束 - 原片开始) / 速度]` 预算时长。超时先删重复、弱相关和冗长背景，再在 1.1-1.2× 范围内调整；不要仅为卡时长切断句子。

## 三、剪辑与字幕

8. **切割**：在句子边界附近检查画面和音频。最终精剪通过解码重编码完成；仅用关键帧复制不能保证准确切点。
9. **倍速**：视频和音频使用相同倍率，视频调整 PTS，音频使用保持音高的 `atempo`。没有音轨的素材与静音故障分开处理。
10. **拼接**：统一分辨率、像素格式、帧率、音频采样率和声道。只有编码参数兼容时才使用 concat 流复制。固定帧率下，使用实际输出帧数累计每段长度，让视频、音频及字幕使用同一个时间基准。
11. **重排字幕**：先定剪辑，再生成字幕。对于原片时刻 `t`、片段起点 `s`、速度 `v`、前序成片累计时长 `O`，新时间为 `O + (t-s)/v`。字幕裁切到保留区间，避免交叉重叠、滚动重复或跨切点残留。
12. **检查并烧录**：保留意大利语重音字符，校正有证据支持的产品名和术语错误；不凭猜测改写数字。按自然短语分组，通常最多两行，数字与单位、产品名保持在同一条字幕中。默认底部居中、白字深色描边，720p 画面字号约 30-34 px、底部边距约 40 px；以实际画面预览调整。

可用 `scripts/retime_subtitles.py` 生成初始 SRT 及时间映射报告。该工具只做去重和时间变换，不代替语义选段、字幕校对和切点判断。用法见参考文件。若导出时对片段时长取整，使用报告中的帧数和累计起点。

## 四、封面制作

13. 在集中介绍产品的区间每 5-10 秒抽取候选帧，生成带原片时间标签的联系表，再对优选区间细查。
14. 优先级：**KOL 手持产品 > KOL 与产品同框 > KOL 自然出镜 > 清晰产品特写**。优先眼睛睁开、表情自然、产品清晰、运动模糊少的画面。
15. 使用真实原片帧制作 1280×720 封面。默认在顶部或底部加半透明黑底、白色产品名标题，不遮挡脸、手中产品或品牌标识。保持比例，避免拉伸；不把 AI 生成的人物手持画面冒充截图。

## 五、交付检查

- 实际容器时长少于 180 秒，文件小于 200,000,000 字节。
- MP4 包含可解码的视频和正确原声；尺寸、编码与音轨符合要求。
- 全片解码检查通过；排查异常黑屏、静音、冻结和不自然切点。检测到静音/黑场时先区分原片内容与剪辑故障。
- 逐段核对所保留口播的字幕覆盖，检查开头、中间、结尾及切点附近的字幕时间；区分技术时间变换验证与实际语音理解核对。
- 检查长字幕、重音字符、数字单位及人物/产品遮挡；每次修改后查看新导出的画面。
- 封面实测为 1280×720，人物及产品清楚，标题拼写正确。
- 包含产品名称、核心卖点和规格；实测、价格或保修只能在原片有证据时纳入。
- 不把抽帧检查称为完整观看，不把解码检查称为听感核对。无法直接审听时明确实际检查范围。

交付 MP4、封面、SRT，并在回复中报告实际时长、实际体积和倍速。提供可点击文件链接，保留选段表及可复用脚本供后续修改。不要在下载地址或交付包中包含凭证、短期媒体签名链接或完整聊天记录。

## 调用示例

> 使用 $youtube-product-short，把这个 YouTube 视频剪成 3 分钟以内的产品介绍，保留原声，加意大利语字幕，体积小于 200 MB，输出 1280×720 的 KOL 手持产品封面。产品：AX9 Max；链接：用户提供的 URL。

用户指定 90 秒、其他语言、禁止倍速、竖屏或不同封面时，应用明确的新要求，其余流程继续复用。
